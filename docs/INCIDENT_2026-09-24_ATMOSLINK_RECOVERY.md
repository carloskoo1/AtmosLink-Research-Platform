# AtmosLink — Incident and Recovery Record
## 24 September 2026

### 1. Scope

Operational incident affecting the AtmosLink scientific dashboard,
scientific QC view, multi-station master publication and dual remote
backup status during the active 6 GHz field campaign.

No evidence of loss of scientific observations was detected during
the recovery process.

---

### 2. Dashboard V4

The `/ui-v4` endpoint initially returned HTTP 500.

The backend remained operational and the scientific APIs continued
responding. The failure was traced to the absence of the active V4
frontend files in the current branch checkout.

The five operational V4 assets were restored from the repository
history:

- `weather_station/dashboard/templates/v4/index.html`
- `weather_station/dashboard/static/v4/css/atmoslink-v4.css`
- `weather_station/dashboard/static/v4/css/scientific-v4.css`
- `weather_station/dashboard/static/v4/js/atmoslink-v4.js`
- `weather_station/dashboard/static/v4/js/scientific-v4.js`

Validation:

- `/ui-v4` -> HTTP 200
- `/api/health` -> HTTP 200
- `/api/latest` -> HTTP 200

The restored V4 assets were permanently incorporated into branch
`feature/atmoslink-ui-v2`.

Git commit:

`bdfdf0f fix: restore AtmosLink V4 scientific dashboard assets`

### 6. Dual remote backup incident

The scheduled backup generated a consistent local archive:

`backup_CU01_20260924_023813.zip`

Exact size:

`142961881 bytes`

The primary Google Drive upload and verification completed
successfully.

The second destination (`atmoslink_drive_unc`) timed out after
600 seconds during the scheduled execution.

The UNC remote itself remained accessible.

A targeted recovery was performed only for the missing second copy,
without regenerating the SQLite backup and without retransmitting the
primary copy.

Manual UNC transfer:

- objects: 1/1
- transferred: 136.339 MiB
- elapsed time: 2m25.3s

Final verification:

- local: 142961881 bytes
- primary Google Drive: 142961881 bytes
- Google Drive UNC: 142961881 bytes

The dual backup redundancy for the 24 September archive was therefore
restored.

The backup timer remained active for the next scheduled execution.

### 8. Engineering observations

The incident demonstrated that the acquisition architecture remained
operational while presentation, schema dependency and backup
redundancy issues were diagnosed independently.

Future work should include:

1. determining the historical origin of the
   `scientific_campaign_6g_integrated_old` VIEW dependency;
2. reviewing the intermittent timeout behavior of the UNC backup
   destination;
3. distinguishing backup states such as HEALTHY, DEGRADED and ERROR
   according to actual redundancy;
4. preserving V4 frontend assets and operational recovery procedures
   under version control.
